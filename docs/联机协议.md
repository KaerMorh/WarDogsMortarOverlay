# 联机协议 v3

传输：WebSocket `/ws`，公网使用 wss。每帧一个 UTF-8 JSON 对象，客户端上行最大 8KiB。版本 v=3；服务器下行最大客户端允许 1MiB（快照）。UUID 小写标准格式；坐标单位与本地 Core 一致，不是米。时间 UTC ISO8601。v3 把任务是否解算的判定完全移到客户端本地，服务端不再从坐标反推 solvedBy，只转发各成员的 target/solved 状态；同时加入炮种字段用于本地推算射程覆盖。v2 客户端必须升级；服务端拒绝版本不符的 join，客户端显示协议不兼容，不尝试误读。

## 客户端消息

连接后 10 秒内发送 join：

```json
{"v":3,"type":"join","requestId":"任意关联ID","uid":"UUID","room":"aabb","callsign":"Alpha","role":"gunner","map":"bakurani","weapon":"mortar"}
```

房间码去空格并转小写，4–32 位 ASCII 字母数字、_、-；Callsign 1–32 Unicode 字符，禁控制字符；角色 gunner/scout；地图 bakurani/ozeti；炮种 mortar/spg，两个角色都必填（scout 也要填，便于切换角色时不必重新协商）。

| type | 字段 | 语义 |
|---|---|---|
| profile | callsign, role, map, weapon | 更新成员资料 |
| origin | point 或 null | 更新/清除公开炮位 |
| target | point 或 null, solved, declined | 更新/清除公开目标；solved 表示本地判定已解算，declined 表示本地判定无法瞄准（预留，客户端暂不发送） |
| publish | taskId, point, requestId | 主动任务；独立于解算目标 |
| sync | requestId | 保持当前连接和 sessionId，返回当前快照；每会话至少间隔 2 秒 |

point 为 `{ "map":"bakurani", "x":80.52, "y":69.85 }`。X 范围 -0.03..163.81，Y -0.01..163.83。目标共享关闭后完全不发送 target 消息。重新打开发送最新值。关闭不是 target:null。solved 与 declined 不能同时为真；两者都只在 role=gunner 且 point 非空时允许为真。

每条消息带 v。资料和炮位/目标按变化发送，目标与炮位合计限制客户端最多 5 次刷新/秒；服务端每连接令牌桶 10 条/秒，突发 20。发布任务优先。服务端完全不解释 solved/declined 的业务含义，只做上述结构校验后原样转发。

## 服务端事件

- snapshot：roomId、room、map（房间建立时地图）、revision、sessionId（自己本次会话）、members[]、identities[]。join 与 sync 都可返回；sync 不建立新会话。
- member：roomId、revision、member；替换该 UID 的完整公开成员状态。入房或重命名可能更新多个成员。
- identity：roomId、revision、identity `{uid,name}`；更新该 UID 的最新公开显示名。
- removed：roomId、revision、uid；移除成员及其悬浮任务，本地历史不删。
- ack：requestId；操作已被服务端接受。publish 在该成员本次会话最近 256 个 taskId 内幂等；客户端不跨重连重试发布。
- error：code、requestId（如有关联）。invalid_message、room_full、server_full、session_replaced。

成员：uid、sessionId、callsign、displayName、role、map、weapon、online、offlineAt（可空）、joined（服务端序号）、origin、target、solved、declined、tasks[]。

客户端的房间码和服务器地址编辑后，在点击加入时生效；当前连接的重连仍使用已加入房间，避免编辑设置意外迁移到另一房间。Callsign、角色、地图和炮种资料允许在当前连接更新。

任务：id、sequence、createdAt、point。每成员 tasks 最新在前最多三条，不再携带 solvedBy——任务是否已被解算完全由客户端本地判定：客户端收到某成员的 member 事件（target/solved）后，自行比对是否命中本地已知的任务点，命中则在本地历史里记一笔并保留（后续该成员切换目标不影响这笔记录）。这意味着后加入房间的客户端看不到加入前已经发生的解算历史，这是本版本接受的取舍。识别显示名统一走 identities 的 UID 最新已知名字；客户端本地记录解算者时应同时快照当时的显示名，因为该 UID 一旦离线且不再被任何成员/任务引用，服务端会回收其身份条目。

事件 revision 在房间实例内递增，ack 不参与；新快照重新建立基线，忽略旧实例/旧连接事件。UID 重进得到新 sessionId，替换原成员，不重放其任务。房间 map 仅提醒依据，不强制全员切换。坐标匹配必须含地图，六位小数规范化（服务端层面不再用于解算归属判定，仅客户端本地去重使用）。

## 资源边界与错误

默认最大 64 房间、32 成员/房间、512 个同时连接（含未入房）。离线成员占房间名额三分钟。每连接有界发送队列 128，慢消费者断开。控制帧心跳 15 秒一次、10 秒超时；C# 持续接收时处理 pong。消息写超时 5 秒。服务端另按直接来源 IP 限制跨连接接入：突发 20 次、持续每秒 0.5 次，桶空返回 HTTP 429；最多保留 4096 个来源桶，空闲十分钟后可回收。

队列还受字节预算约束：每连接 1MiB，全服务合计 32MiB。重复的 profile/origin/target 仅回复 ACK，不重复广播，不提高房间 revision。停机关闭 WebSocket；/readyz 返回 503。每分钟日志只有聚合统计，没有房间码与玩家坐标。

C# 同样启用主动心跳超时，避免网络黑洞中一直显示在线而不重连。三分钟离线保留从服务端确认断线开始计时。

客户端显示连接/错误状态，发送操作 8 秒未收到 ack 则提示"未确认"，不声称任务发送成功，也不自动跨会话重发。同 UID 替换后的客户端需停止自动重连，避免两台复制身份的程序互踢。
