# PZH QTE 离线识别方案与测试

2026-09-21：已实现离线识别原型并测试。此阶段只处理图片，不接入设置 UI、实时截屏、键盘监听或自动输入。

## 样本标注

三个原始 JPEG 只重命名，图片内容保持不变。文件名中的方向按从左到右排列：

| 文件（位于 test/） | 人工标注 | 实际识别 |
| --- | --- | --- |
| Snipaste_2026-09-21_04-12-02_QTE_左左左下.jpg | ← ← ← ↓ | 左左左下 |
| Snipaste_2026-09-21_04-12-13_QTE_下左下左.jpg | ↓ ← ↓ ← | 下左下左 |
| Snipaste_2026-09-21_04-12-27_QTE_上上下下.jpg | ↑ ↑ ↓ ↓ | 上上下下 |

识别器只接收 Bitmap 和可选区域，不读取文件名。测试程序从文件名读取预期答案，再与像素识别结果对照；答案不传入算法。

## 算法

使用 C#、System.Drawing 和现有便携 .NET SDK。项目为独立 Windows 控制台程序，无新增 NuGet 包，无 OCR、AI 模型或外部运行时。

1. 默认截取全图 X=45.5%、Y=55.7%、宽=9%、高=4.2%。2560×1440 对应约 (1165, 802, 230, 60)。调用者也可以传入自定义像素区域。当前原型的尺寸筛选按全图高度缩放，因此应传入完整截图，不能直接把小裁图当作完整画面。
2. 将区域内像素转换成亮色掩码：RGB 最小通道至少为 160，最大与最小通道差不超过 55，以保留偏白箭头。
3. 用八邻域连通域找独立形状。以 1440 高度为基准，宽高必须在 20～45 像素内，宽高比 0.65～1.55，填充率 0.35～0.85，过滤边框、细线和碎点。
4. 每个候选轮廓归一化到 32×32，与同一几何箭头旋转得到的左、上、右、下四个模板比较，评分采用交并比（IoU）。不从某张测试图提取专用模板。
5. 最佳分数至少 0.70，且领先次佳方向至少 0.12，才接受这个箭头。分数是形状相似度，不是正确概率。
6. 必须恰好识别出四个候选，按 X 坐标排序。再检查横向排列：中心高度差不超过平均箭头高度的 20%，相邻 X 间距最大/最小不超过 1.25，间距在平均高度的 1.1～2.5 倍内。
7. 返回完整方向串及各箭头坐标、分数、分差；候选不足、过多、低分或排列异常均返回不接受，不猜测缺失方向。

算法入口：`qte-tests/QteRecognizer.cs`。独立验证入口：`qte-tests/Program.cs`。

## 边界与后续接入

- 三张图属于同一场景，是开发验证集，不能把这次通过率当作跨场景准确率；阈值仍需要更多独立样本验证。
- 缩放测试是对原截图做图像缩放，不是对应分辨率下的真实游戏渲染测试。超宽屏、游戏 UI 缩放、HDR 和不同亮度未验证。
- 当前真实样本没有右箭头。算法包含右方向，但右方向尚无真实样本验收。
- 背景反例数量有限；深色、变色、动画中的箭头可能被拒绝，不能据此认定 QTE 已消失。
- 当前只识别方向，不判断按键是否被游戏接受、四组是否完成、等待超时是否重置。
- 后续实时接入时，在独立工作线程只处理小区域，并用连续帧稳定结果决定是否允许输入；必须另行验证重复组合、换组动画、失败重置与消失检测。
- 区域设置持久化、游戏客户区/DPI 换算、键盘透传、取消与四组执行状态机的首版实现见下节；游戏内表现仍待验收。

## 2026-09-21：自动装弹首版接入

- 识别器已迁入 `src/PzhQteRecognizer.cs`，`qte-tests` 链接同一源码。新增 `RecognizeRegion(Bitmap, referenceClientHeight)`，箭头尺度仍以完整客户区高度计算，结果坐标相对小区域。
- `Preferences.PzhReload` 独立于炮位校准设置，默认关闭。配置含换弹键、客户区比例区域、组数和时间参数；加载时补默认值并限制无效数据。
- 设置的实验区支持框选、恢复区域、测试识别和状态查看。用户在设置里点击“框选识别区域”或“测试识别”后，程序等待下一次换弹键；用户可直接回到游戏射击并按 R，没有倒计时或进程绑定。框选打开覆盖层；测试识别最多等待配置的首次等待时间，连续两帧可信后显示方向与单帧截图＋识别耗时，不发送方向键。
- 区域相对按键当时前台窗口的客户区保存。拒绝本应用窗口；使用 WPF 设备变换处理框选坐标。当前为避免混合 DPI 错位，目标窗口 DPI 与系统 DPI 不一致时拒绝运行。
- 低级键盘钩子只观察换弹键、Esc 和人工方向键。原换弹键透传；按下沿启动，注入事件不回触发。`SendInput` 按扫描码发送扩展方向键。任务在后台执行，并在取消和结束时释放本服务按住的键。
- 单任务循环要求连续两帧方向及位置稳定。每组四键完整提交后才计数。识别器只接受当前画面中稳定的四个白色箭头；按过后变绿或变红的箭头自然不再组成有效结果，下一组重新出现四个白色箭头即可继续，方向串是否相同不参与换组判断。默认最多提交四组，状态只写“已提交”，不声称装弹成功。
- 自动输入以总测试开关、子开关、SPH-2 模式、未暂停、无录键和任务菜单为门禁。用户按换弹键时取前台窗口作为本次目标，并在任务内核对原窗口句柄与 PID；本程序窗口不能作为目标。Esc、人工方向键、焦点丢失、开关/模式变化、框选、参数修改及退出会取消任务。正常与简化计算 HUD 都显示开关、执行状态和最近识别方向。

## 2026-09-22：交互与连续相同 QTE 调整

- “测试功能”改为两个互不依赖的子项：“显示连接功能”和“自动装弹”。勾选自动装弹后立即安装换弹键监听并显示其设置；不再要求同时开启连接功能。
- HUD 自动装弹状态只在已勾选自动装弹且炮种为 SPH-2 时显示，迫击炮与关闭状态均隐藏。
- 运行中再次按换弹键会取消上一任务，待其释放可能按住的方向键后立即以本次前台窗口启动新流程。
- 换组不再比较方向串是否变化，也不要求程序实际采样到短暂的绿色/红色中间帧；当前画面重新稳定识别出四个白色箭头即可进入下一组。新增三项变绿箭头图片用例，验证变色箭头不会被当作白色 QTE；当前完整图片测试为 47/47 通过，Release 构建通过。
- 上述换弹键打断、游戏内绿色反馈和连续相同 QTE 仍需真实游戏交互验收；本轮没有服务器操作、部署或推送。
