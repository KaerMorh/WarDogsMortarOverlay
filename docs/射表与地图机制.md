# WarDogs 射表与地图机制

核对日期：2026-09-06。基础项目：[apollyon-sys/wardogs-calculator](https://github.com/apollyon-sys/wardogs-calculator)，对应用户使用的网站 https://wardogs-artillery.com/ 。

本文依据检索时 GitHub main 分支的源码与数据；尚未锁定提交 SHA，且未能直接读取线上站点 JSON，因此不宣称与用户此前使用的部署版本逐字一致。开发前应固定上游提交、保存完整 JSON 与许可，并与在线结果对照。

## 已确认需求

- 用户实测该网站的迫击炮结果非常准确，首版目标是复现其默认计算行为。
- “攀枝花”指 SPH-2；上游内部 ID 为 `spg`。
- 游戏流程：M 打开地图 → 右键位置 → 菜单“读取坐标” → 游戏自动打开聊天输入栏并填入类似 `x11.64 y41.33` 的文本 → 用户 Ctrl+C 复制到系统剪贴板。
- 应用分别保存炮位与目标，显示距离、仰角密位 MIL、方位角。炮位指武器实际位置。
- 上述游戏交互由用户确认；本轮未进行本机游戏操作测试。

## 1. 坐标与计算

原点 O=(ox,oy)，目标 T=(tx,ty)，比例 s 为地图的 coordinateMetersPerUnit。

```text
dx = tx - ox
dy = ty - oy
distanceMeters = hypot(dx,dy) * s
azimuthDegrees = (atan2(dx,dy) * 180 / PI + 360) % 360
```

源码约定 X 正向为东、Y 正向为北；北/东/南/西分别为 0/90/180/270 度。屏幕像素 Y 方向不能直接套用。当前两图 s=100，因此 0.01 坐标单位=1 米。

计算使用未舍入的距离，显示时才舍入：距离整数米、方位角一位小数、MIL 整数或整数区间。移植到 C# 时注意其默认中点舍入与 JavaScript Math.round 的差异。重合两点的方位角在几何上无定义，我们的应用应显示“—”，避免把 atan2(0,0) 的数值作为有效方向。

来源：[results.js](https://github.com/apollyon-sys/wardogs-calculator/blob/main/js/features/results.js)。

## 2. 两种武器的射表

射表条目均为 `[距离米, 仰角MIL]`。MIL 是查表输出，不是把方位角换成密位。两种武器共用插值器，两张地图共用同一武器数据文件。

| 参数 | 迫击炮 | SPH-2（攀枝花） |
|---|---:|---:|
| 内部 ID | mortar | spg |
| 有效射程，含端点 | 132–684 m | 780–2629 m |
| 配置仰角范围 | 150–850 MIL | 20–1390 MIL |
| 弹道分支 | single | low / high |
| single 原始数据覆盖 | 80–697 m | 无 |
| low 原始数据覆盖 | 无 | 1181–2629 m |
| high 原始数据覆盖 | 无 | 735–2629 m |

“原始数据覆盖”不等于“有效射程”：迫击炮 80–131 m 等样本虽然存在，也不能被当作有效解。基础求解函数先按 minRange/maxRange 检查（容差 1e-6 米），再查各分支；配置的仰角上下限在该函数里没有另行用于裁剪输出。

SPH-2 的有效区间：780≤d<1181 m 只有高抛解；1181≤d≤2629 m 可以分别得到低抛和高抛解。无某分支解时不能从另一分支外推。

### 插值器必须保留的行为

1. 清理非数值样本，按距离升序、再按 MIL 升序排列；同距离归成一组。
2. 距离与某组相差不超过 1e-6 m 时，精确命中：单条返回 MIL；多条返回 minMil/maxMil 区间。
3. 未精确命中则找左右距离组；找不到左右组就返回无解，不外推。
4. 左组选择最接近右组 MIL 平均值的值，再从右组选择最接近所选左值的值；等距时保留排序中较早的值。
5. 执行线性插值 `M=M1+(d-D1)/(D2-D1)*(M2-M1)`，最后显示时舍入。

来源：[weapons.js](https://github.com/apollyon-sys/wardogs-calculator/blob/main/js/features/weapons.js)、[完整 weapons.json](https://github.com/apollyon-sys/wardogs-calculator/blob/main/data/weapons.json)。本文凝练机制与关键点，不手抄全表；实现时必须导入完整数据。

### 可用作回归基准的点

| 武器/分支 | 距离 | 未舍入结果或显示区间 |
|---|---:|---:|
| 迫击炮 single | 132 m | 850 MIL |
| 迫击炮 single | 305 m | 685 MIL（由 300/690 与 310/680 插值） |
| 迫击炮 single | 684 m | 150 MIL |
| 迫击炮 single | 700 m | 超出射程 |
| SPH-2 high | 780 m | 1390 MIL；low 无解 |
| SPH-2 low | 1181 m | 20 MIL |
| SPH-2 low / high | 2046 m | 220 / 1040 MIL |
| SPH-2 low / high | 2629 m | 600 / 610–620 MIL |

最后一项尤其重要：高抛表在 2629 m 同时有 610、620 两个值，不能用普通字典覆盖掉其中之一。

## 3. 当前两张地图的参数

地图注册表只列出 Bakurani 与 Ozeti。下表是当前 main 数据，不沿用旧文档中的整齐 0–163.84 瓦片边界。

| 字段 | Bakurani | Ozeti |
|---|---|---|
| id | bakurani | ozeti |
| coordinateMetersPerUnit | 100 | 100 |
| w / h 原始配置 | 16 / 16 | 32 / 32 |
| bounds X | 23.35–133.60 | 57.58–143.07 |
| bounds Y | 19.34–129.65 | 21.81–99.56 |
| tileBounds X | -0.03–163.81 | -0.03–163.81 |
| tileBounds Y | -0.01–163.83 | -0.01–163.83 |
| 瓦片参数 | 256 px，缩放 0–7，WebP | 256 px，缩放 0–7，WebP |
| 瓦片目录 | maps/tiles/bakurani | maps/tiles/ozeti |
| 地形清单 | data/terrain/bakurani/manifest.json | data/terrain/ozeti/manifest.json |

来源：[地图列表](https://github.com/apollyon-sys/wardogs-calculator/blob/main/maps/index.json)、[Bakurani](https://github.com/apollyon-sys/wardogs-calculator/blob/main/maps/bakurani.json)、[Ozeti](https://github.com/apollyon-sys/wardogs-calculator/blob/main/maps/ozeti.json)。

两图 tileBounds 的跨度均为 163.84 坐标单位，即 16384 米，这是配置的瓦片覆盖跨度，不等同于实际可玩区域。w/h 不应取代 coordinateMetersPerUnit 用来计算粘贴坐标的距离。bounds、tileBounds 和地形覆盖范围各有用途，不应混用为输入合法性硬边界；尤其不能据 bounds 拒绝用户的示例 x11.64。

对于首版的纯坐标计算，同一武器、同一组坐标在这两张图会得到同样的默认距离、方位角和密位。地图选择仍用于保存各图炮位/目标及以后加载地图、地形资源；切图应清除当前有效解，防止混用坐标。

## 4. 地形与车辆姿态

当前配置 `automaticMilCorrection=false`、`flatTableAuthoritative=true`：默认以平地射表为准。地形数据能提供 ΔZ=目标高度−炮位高度。

修正此前调研表述：当前代码已有 SPH-2 实验性地形修正，`available=true`，但 `defaultEnabled=false`。用户主动开启后，仅在对应分支解析状态为 SAFE_CONSENSUS 时采用修正，其余情况回退平地射表；车体倾斜修正仍关闭。首版复现默认射表，实验模式后续单独评估。SPH-2 的车辆调平提示可以保留。

来源：[terrain-context.json](https://github.com/apollyon-sys/wardogs-calculator/blob/main/data/ballistics/terrain-context.json)。

## 5. 开发验收要点

- 与固定上游版本比对：所有射表节点、相邻节点中点、各射程边界、SPH-2 最大射程重复距离、无解分支。
- 坐标验证：东西南北和四象限、重合点、带符号小数、原样 x11.64 y41.33、空白及不合法聊天文本。
- 用用户在游戏内复制的两点同时输入网站与应用，核对距离/MIL/方位角，并在游戏中验证完整交互。
- 计算通过后再检查快捷键冲突、复制失败、重复坐标、切图、DPI/多屏以及无边框窗口中的悬浮显示。
