# 输入交互与开发方案（修订提案）

更新：2026-09-06。本文记录用户已确定的要求；标为“补充约定”的内容是为消除状态歧义提出的设计。尚未实现软件。

## 1. 技术与开发位置

- 技术栈：C# + WPF + WebView2。WPF 承载可交互 HUD 和桌面功能，WebView2 承载大型交互地图。
- 后续开发目录：P:\Projects\WarDogsMortarOverlay。源代码、地图资源和构建输出优先放 P 盘；SDK/缓存位置在配置环境时另行安排。
- 保留三种输入模式：连续目标、精确手动、智能。建议首次启动选智能模式。
- 不检查游戏进程或前台窗口，不根据游戏状态限制显示、快捷键或剪贴板接收。
- HUD 始终可交互，不做鼠标穿透，不要求切换交互模式。用户在游戏释放鼠标时直接操作 HUD。
- 游戏输入流程：M → 地图右键 → 读取坐标 → 聊天框填入 x/y → Ctrl+C。

## 2. 三种模式

### 连续目标模式

固定炮位，持续以有效剪贴板更新作为新目标。炮位设置动作进入一次性炮位等待，再按取消；成功后锁定炮位并恢复连续目标接收。目标选定动作明确读取当前剪贴板。暂停时停止被动更新，恢复后只处理新的复制事件。

### 精确手动模式

不被动接收坐标。炮位设置、目标选定分别将当前剪贴板的有效坐标用于对应位置；无有效坐标时仅在 HUD 提示，已有位置不变。允许明确重复提交。

### 智能模式

区分“就绪、等待炮位、等待目标、已暂停”，HUD 永久显示当前状态。就绪状态不持续自动替换目标，等待由相应动作开启，成功接收一次后返回就绪。

#### 炮位设置（用户要求）

1. 若正在等待炮位，再按停止该等待，不改已有炮位。
2. 否则立即读取剪贴板。
3. 坐标有效且与已有炮位不同：立即设为炮位。
4. 无有效坐标，或坐标与已有炮位相同：进入“等待炮位”，等待后续复制。
5. 没有已有炮位时，有效剪贴板坐标直接采用。

#### 目标选定（用户要求）

1. 立即读取剪贴板。
2. 当前坐标与炮位相同，或与上次目标相同：进入“等待目标”。
3. 坐标有效且与两者均不同：立即设为目标。
4. 无有效坐标时进入“等待目标”（补充约定）。

#### 等待、停止与恢复的补充约定

- “上次一致”指当前地图最后一次成功设定的目标坐标；按解析后的数值 X/Y 比较，不比较原始字符串或尾随文字。
- 同时只等待一种位置；等待目标时执行炮位设置，就切换为炮位动作，反之亦然。
- 等待期间忽略无关文本。炮位等待仅接收与旧炮位不同的有效坐标；目标等待仅接收与炮位、上次目标均不同的有效坐标。相同坐标不结束等待。
- 等待不自动超时。等待炮位可通过再次执行炮位设置取消；等待目标可通过暂停或模式切换取消，重复执行目标选定仍按上述规则判断。
- 停止智能模式：取消当前等待并暂停被动接收；恢复后回到就绪，不自动读取旧剪贴板，也不恢复旧等待。
- 暂停期间，显式炮位/目标动作恢复智能模式并执行对应动作，HUD 提示已恢复；这是便于操作的补充约定。
- 同坐标确实需要再次采用时，可切换精确手动模式或在 HUD 明确手动设置。

## 3. 快捷键按功能定义

所有动作都可自行绑定、修改或清除快捷键，保存后下次启动沿用。提案不固定具体键位。HUD 提供对应按钮，快捷键与按钮调用同一动作。

| 功能 | 行为 |
|---|---|
| 炮位设置 | 按当前模式执行炮位读取或等待 |
| 目标选定 | 按当前模式执行目标读取或等待 |
| 停止/恢复智能模式 | 智能模式暂停/恢复；连续模式复用为暂停/恢复连续接收；精确模式仅提示当前是手动模式 |
| 隐藏/显示 HUD | 切换可见性，不改变采集状态；隐藏后仍可用同一快捷键恢复 |
| 模式切换 | 连续目标 → 精确手动 → 智能 → 连续目标，HUD 显示切换结果 |
| 地图切换 | Bakurani ↔ Ozeti；HUD 与大地图同步 |

快捷键重复、已被系统占用或注册失败，都只在 HUD 近期提示区显示；修改失败保留原绑定。按住按键不应重复触发切换。

模式切换取消未完成等待，保留炮位和目标。地图切换取消等待；各图独立保存炮位与目标，切回地图直接恢复并计算，不设历史确认步骤。首次切换到无数据地图时显示“待设置炮位/目标”。

## 4. 坐标解析与防错

- 优先解析明确的 X/Y 标签，大小写不敏感，支持小数、符号、标签周围空白以及明确的冒号/等号分隔。
- 必须接受尾随无用文字：`x12.11 y11.11大大的asadasd` 应得到 X=12.11、Y=11.11。尾随文字不参与坐标值或重复判定。
- 数字按完整合法数值片段解析，遇普通尾随文字停止；不能把 `y11.11.22` 等畸形数值静默截成看似合法值。X/Y 缺一项或同一文本存在多组明确坐标时，提示无法确定，不猜测。
- 自动/智能接收要求 X/Y 标签；纯两数字输入只在显式手动输入中支持，避免普通聊天数字被当作坐标。
- 不要求整个剪贴板只有坐标，不记录尾随聊天内容，也不覆盖用户剪贴板。
- 同一剪贴板事件只处理一次；数值重复如何处理由模式决定。连续/手动模式允许重复确认，智能等待遵循上述不同坐标条件。
- 剪贴板暂时被占用时有限重试；读取失败不采用旧文本冒充新结果，等待中则保持等待。
- 位置、来源、时间和计算结果统一更新。解析失败保留上次成功结果，同时显示本次未更新。
- 炮位改变后清除旧目标的当前有效解，提示重新选定目标，避免沿用过期组合。
- 有效坐标超出射程时仍更新目标，保留距离、方位角；MIL 显示“—”，附低干扰状态“超过最大射程 125 m”或“低于最小射程 20 m”。不弹框、不闪烁，不显示旧 MIL。
- 两点重合时方位角和 MIL 均为“—”，状态显示“目标与炮位重合”。

## 5. HUD 与地图联动

- HUD 可直接点击按钮、展开目标/来源列表、调整布局；不做穿透开关或交互模式。
- 始终显示地图、武器、输入模式及采集状态；等待炮位、等待目标、就绪、暂停使用文字配合颜色/图标区分。
- 距离、MIL、方位角为主指标。SPH-2 明确区分高抛与低抛，不自动悄悄切换分支。
- HUD 内提供近期提示区：默认显示最近一条，可展开最近若干条。重复错误合并；状态标识常驻，短暂提示可淡出。
- 不出现任何弹窗：包括解析失败、热键冲突、超程、设置校验和地图加载错误。设置、输入、确认均使用已有窗口内的区域或 HUD 展开面板。
- 点击悬浮窗后的焦点行为需要实测，文本输入可获取焦点；不通过检查游戏进程实现。
- 大地图拖动目标实时刷新 HUD，剪贴板设定位置也同步地图标记。坐标与射表计算使用统一状态与同一计算核心。
- 地图拖动期间，将外部坐标更新暂存，避免目标跳动；结束时在 HUD 提示有新输入，由用户决定采用（提案补充约定）。
- 以后房间共享作为另一坐标来源接入，保留提供者和时间；本轮不实现联机。

## 6. 软件结构与阶段计划

1. 环境与计算基础：在 P 盘配置工程，固定上游射表和两图配置，保留许可证；独立实现解析与计算并对照上游结果。
2. 可操作 HUD：WPF 置顶交互面板、指标、状态标识、近期提示、快捷键自定义与设置保存。
3. 三模式输入：剪贴板事件监听、智能状态转换、暂停恢复、模式/地图切换；覆盖相同坐标、垃圾尾缀、读取失败与超程。
4. 地图联动：WebView2 大地图、炮位/目标标记、拖动实时计算，以及剪贴板与地图同步。
5. 验收与发布：验证焦点、多屏/DPI、热键冲突、无弹窗、隐藏恢复和离线运行；再打包给队友使用。

首版验收标准：完整三模式与六项功能动作可用，支持两图/两武器，带尾缀的 X/Y 可正确解析，大地图拖动与 HUD 实时同步。OCR、实验性高差修正与多人房间列入后续阶段。


## 7. v0.2 体验修订（已实现）

启动仅显示 HUD；标题、数字或空白可拖动。控制面板、透明三指标、小圆球三种形态可互切，并记忆位置与外观。控制面板和透明模式均保留炮位、目标、暂停、炮种、地图、模式操作。齿轮内提供快捷键录入、背景浓度、整体缩放、手动坐标、打开地图和退出。主程序将战术地图与设置独立分页。两图补齐 Tower 编号，可点选为目标。
