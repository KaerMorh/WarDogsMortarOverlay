# 自动更新与发布指南

## 用户使用

0.5.0 没有自动更新入口，需要最后手动安装一次 0.6.0。此后在 HUD 或大地图的设置顶部检查、下载、重启安装。小红点表示检测到比本机新的正式版；打开设置不会消除红点，更新到新版后再检查便消失。小球模式可从右键菜单的设置进入。

启动时默认后台检查一次，可关闭。没有常驻后台服务，不强制更新，不主动重启电脑。断网或下载失败不影响当前软件使用。下载暂停后重新下载，不支持断点续传。自动安装仅支持安装版；便携版显示安装提示。

## 开发机前提

- PowerShell 7（`pwsh`）、项目 `.tools/dotnet`、Inno Setup 6、Node.js、Git、GitHub CLI。
- `gh auth status` 必须成功；失效时在自己的终端执行 `gh auth login -h github.com`。不要把 token 发到聊天或写入项目。
- 签名私钥默认在 `.tools/update-signing/private.pem`，被 Git 忽略。**请单独安全备份这个文件。** 客户端内置 `src/update-public.pem` 公钥，公钥必须提交。
- 不得重新生成密钥代替丢失的原私钥；已安装客户端只信任原公钥。丢失私钥需要用户手动安装带新公钥的版本，或事先设计密钥轮换。

## 每次发布

1. 修改 `src/WarDogs.csproj` 的 `<Version>`，使用递增的三段数字，例如 `0.6.1`。同步 README、界面版本文字和安装脚本的备用版本号。
2. 新建 `installer/release-notes-0.6.1.md`，写本次用户能感知的变化。
3. 执行构建、测试并检查变更，提交需要发布的源码。不要提交 `.tools`、`app`、`artifacts`、用户配置和私钥。
4. 在仓库根目录运行：

```powershell
pwsh -File ./publish-release.ps1
```

脚本检查登录和已跟踪文件变更，构建自测及上游比对，打包安装器，生成签名清单，推送当前提交，创建草稿 Release 并上传四个附件，最后设为正式最新版。它不会替你提交代码。必须先确认未跟踪的源码和文档也已加入提交。发布版本必须唯一；不要改写已经发布版本的附件。

附件：

- `WarDogsOverlay-版本-win-x64-Setup.exe`
- 同名 `.exe.sha256`
- `update.json`
- `update.json.sig`（原始二进制签名）

只生成本地安装包与清单：

```powershell
pwsh -File ./build-installer.ps1
pwsh -File ./create-update-manifest.ps1
```

已有经过验证的同一源码构建产物时可执行 `publish-release.ps1 -SkipBuild`。不要让旧安装包与新提交混用。

## 更新链路与故障处理

客户端固定读取仓库 `releases/latest/download/update.json` 和 `.sig`，先验 RSA SHA-256 签名，再校验版本、安装包地址、大小和 SHA-256。清单只允许此仓库对应版本的安装包地址。清单签名不同于 Windows Authenticode 签名，不会消除 Windows 对未签名安装包的提示。

下载写入 `%LOCALAPPDATA%/WarDogsOverlay/Updates/<随机目录>`，校验成功才变成 `Setup.exe`。临时目录内的更新助手等待当前进程退出，确认同目录没有其他实例，再次校验并锁定安装包，备份原目录 `UserData/settings.json`，调用 Inno Setup 静默升级到原路径，成功后启动软件。PowerShell 被组织策略禁止时，可从发布页手动下载安装。

日志和备份位于上述下载目录：`install.log`、`update-error.log`、`settings.backup.json`。从 0.6.2 起，下载成功时同时保存签名清单；下次启动先离线验签及验哈希，恢复“重启并安装”，关闭自动检查也可恢复。下载未完成时退出仍需重新下载。

缓存会自动清理：启动清理未完成下载、损坏包和已安装版本的包；成功检查更新或下载后清理被替代的包；安装成功释放文件锁后删除安装包，若 Windows 仍占用则下次启动重试。0.6.0/1 无签名元数据的遗留包可在联网取得有效清单后复用，已安装版本或超过七天的遗留包会删除。清理只针对专用缓存目录内的已知更新文件，保留设置备份、日志和其他文件，不递归删除目录。

0.6.2 起同一 Windows 会话只允许一个实例，重复打开唤回已有 HUD。退出、安装失败时不会强杀其他进程。安装器不是事务式回滚系统；安装中断可重新运行对应安装包修复，配置损坏可从备份恢复。

发布中断时先用 `gh release view v版本` 检查草稿及四个附件；缺哪个补传哪个，确认后再通过 `gh release edit v版本 --draft=false --latest` 发布。未完成附件上传前不要设为正式版。

## 发布验收

- 单元测试：签名篡改、错误密钥、错误版本/URL/大小/哈希均拒绝；只接受更高正式版。
- 本机演示检查：设置更新面板、正常/简化/小球入口、大地图入口、小红点与下载状态。
- 安装版：旧版升级到新版，自定义路径含空格或中文，UserData 保留。
- 更新安装：等待退出、运行中存在其他实例、下载取消/断网、损坏包、安装失败。
- 发布后：四个附件齐全，公网获取清单和签名成功，安装包 SHA-256 与本地一致。

GitHub 无法访问时检查会失败并允许重试；本版未启用镜像或增量更新。发现版本问题时建议发布更高补丁版本修复；客户端不会自动降级。
