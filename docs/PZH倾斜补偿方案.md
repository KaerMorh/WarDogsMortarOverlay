# PZH 倾斜补偿接入方案

日期：2026-09-17。状态：第一版已实现并完成本地自动验证，待游戏实射验收。

## 目标与第一版范围

为 SPH-2/PZH 高抛加入按当前停车状态校准的倾斜补偿。玩家记录试射参数和落点，应用估计两个世界方向倾斜参数；启用后直接显示补偿后的方位角与密位。无需输入车头朝向或观察实际姿态。

用户接受现有模型达到的精度，优先完成实用流程。第一版保留平地射表作为基准，不加入未知高差估计、额外射程偏移参数或自动图像识别。迫击炮继续原流程。全部算法采用原生 C#，不运行研究用 Node 脚本，不增加第三方数学库。

## 使用流程

1. 设置地图、炮位、SPH-2，打开“PZH校准”小窗口。
2. 点击“开始新校准”：为当前地图与炮位新建记录，进入原始高抛试射模式。
3. “本发参数”自动带入当前原始高抛方位、密位，可手动修改；因此也支持没有目标坐标、直接打90°/1300 MIL的试射。
4. 点击“记录这发”锁定炮位、地图、实际准备使用的方位和密位；按该参数在游戏中开火。
5. 点击“读取落点”，在游戏里复制落点坐标。下一次有效复制只记作这发落点。也可在窗口粘贴坐标。此时不覆盖当前目标，不发布房间任务。
6. 换一个射向重复。两发可求解并启用；窗口支持继续增加、删除或修改记录后重新计算。两发提供的约束不足以求解时，说明需补一个不同方向的样本。
7. 点击“计算并启用”。关闭窗口后继续正常选目标，HUD显示应用补偿后的高抛方位与密位。

“记录这发”和“读取落点”是两个明确阶段，不能让复制落点时变化的当前目标回写本发射击参数。同一时间最多有一发等待配对；未完成时允许取消或编辑，不隐式覆盖。第一版校准采样统一用原始高抛解，进入采样时暂停当前补偿，防止把修正后角度误当原始角度；若游戏中实际使用了其他参数，应在该行填入实际参数。

剪贴板落点捕获与发布任务捕获互斥，开始一项时取消另一项，界面明确显示当前等待用途。待捕获期间无效坐标不提交，取消后恢复普通坐标接收。暂停、关闭窗口、切图或炮位变化时结束等待，避免后台误吞坐标。

## 界面

使用独立、可拖动 WPF 小窗口；HUD右键、设置的坐标/工具页提供“PZH校准”入口，可绑定一个打开快捷键。

窗口内容：

- 当前炮位、补偿开关、开始新校准。
- 本发方位角、密位，记录这发、读取落点、取消。
- 样本列表：编号、方位、密位、落点、模型横向残差；可修改、删除。
- 计算并启用、关闭补偿；简短状态如“已校准 · 3发”。

正常HUD、小球、简化HUD统一使用同一份显示解：启用时显示“高抛 MIL”和“补偿方位”，状态行显示“高抛 · 倾斜补偿”；关闭后恢复现有低抛/高抛显示。窗口中可查看原始与补偿读数差值，日常HUD不堆叠两套数字。

当前Solution只有一个Azimuth，但低抛和高抛经过三维补偿后不共用一个方位。因此第一版补偿开启时仅提供高抛读数，不能显示“原始低抛/补偿高抛 + 一个补偿方位”。需要低抛时关闭补偿，恢复原始双分支。

距离、地图目标点及共享目标始终表示真实目标；不为补偿伪造或平移目标坐标。

## 数学与数据

新增TiltCompensation.cs，承载样本、标定结果、拟合与逆旋转。纯数学部分不依赖WPF、剪贴板或网络。

每发保存：地图、炮位、实际指令方位、实际指令密位、高抛分支、落点、时间；目标坐标只作可选追溯。结果保存两个世界倾斜参数、模型版本、角度换算系数、样本残差。窗口不要求用户理解这些内部参数。

拟合采用现有研究模型：以东/北/上坐标构造名义发射单位向量，同一个两参数三维旋转作用于同一停车状态的各发向量；最小化预测方位与实际落点方位的环绕角度残差。每发射程、高差不参与拟合。先采用k=0.001 rad/MIL，并在模型版本中固定，后续更改时不静默解释旧校准。

补偿时先用原Ballistics.Solve取得目标世界方位a、原始高抛密位M，构造单位向量u；计算Q的逆旋转Q^T*u，提取命令方位和仰角，再将仰角换回密位。必须同时求两个输出，不采用固定减一个角度的近似。内部保留浮点精度，只在HUD显示时舍入。

处理角度0/360环绕、无解、非有限数、重合点和密位区间。若原高抛解是区间，第一版使用区间中点构造一个明确解；实际记录的发射参数始终为单值。补偿后的仰角超出当前武器配置可设置范围时显示“补偿后超出仰角范围”，不夹紧数值、不悄悄回退并继续标注补偿。

## 生命周期

校准绑定当前地图与炮位及一次停车会话。

- 正常换目标不会清除校准。
- 炮位坐标改变、切图、重新开始校准时停止使用旧补偿。
- 提供“车辆已移动 / 重新校准”操作，处理坐标未更新但姿态已经改变的情况。
- 切到迫击炮时不应用；同一次停车会话内切回PZH可恢复开关。
- 样本、启用状态和结果随其他本地偏好保存在UserData/settings.json；重启应用保留记录和开关，但炮位不匹配或曾经变更后不会应用旧补偿。
- 不因历史炮位坐标再次相同就自动认定姿态相同。

旧状态六发、新状态两发分别作为开发回归样本，不把实验得到的倾斜硬编码成所有玩家的默认补偿。

- Controller.cs维护校准状态与一次落点捕获。现有Result保留给原业务，新增明确的显示解，将原始结果与补偿高抛成对管理；HUD从显示解取数，不在每种HUD内重复计算。
- PzhCalibrationWindow.cs提供独立窗口；SettingsPanel.cs、HudWindow.xaml.cs增加入口和状态。
- 校准文件与现有UserData路径规则一致，原子保存，不进入发行包。
- 联机继续共享真实炮位和目标，补偿属于本地车辆状态，不新增服务端协议字段。校准读取落点不得触发普通SetTarget或发布任务。检查现有任务“已解算”语义：若补偿模式无法给出可设置指令，应让本地可射击状态反映该结果，服务端仍只转发状态。

## 2026-09-17 实现结果

- HUD正常和简化形态的信息栏在SPH-2下显示独立按钮：尚未校准、重新校准、校准已关闭或需重置校准；点击打开独立窗口。迫击炮下隐藏。
- 校准窗口已支持开启/关闭补偿、带入当前原始高抛解、从剪贴板智能读取（当前无有效坐标时等待下一次复制）、手动输入、删除选中、重置全部、保存以及关闭时保存确认。
- 炮位变化会保留样本并永久标记NeedsReset，HUD和通知提示重置；即使坐标后来回到旧值也不会自动重新启用。重置才绑定当前炮位。
- 补偿启用且有效时，HUD主方位和MIL显示补偿后的高抛参数；目标信息行追加“校准后 方位 / MIL”。低抛不与补偿方位混用。关闭补偿保留样本并恢复原始低/高抛显示。
- 联机协议和Go服务端未改变；共享的仍是真实炮位和目标。
- 核心测试275项通过，其中新增六发拟合、逆旋转、最小样本和零倾斜回归；完整Go、更新、射表、联机和重启构建流程通过；WPF自动验证通过HUD入口、窗口控件、补偿显示与炮位变更失效。自包含客户端已输出到artifacts/multiplayer/client。

## XY线性补偿追加

在倾斜姿态模型之外，校准窗口提供可切换的XY线性模式。该模式记录瞄准点A与实际落点B，并使用`Δ=A-B`作为世界坐标固定补偿；正常目标T按`T+Δ`重新计算SPH-2高抛方位与MIL。一组A/B即可启用，多组时取平均值并显示以米计的离散度。

A可直接输入或带入当前目标坐标，也可输入方位与高抛MIL。应用使用当前炮位和SPH-2高抛射表实时双向换算A坐标与方位/MIL。B沿用智能剪贴板和手动坐标输入。两种模式的数据分别保存，启用状态应用于当前选中的模式；炮位变化后均停止使用，已有数据继续保留到用户主动重置。
