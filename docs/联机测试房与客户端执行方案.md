## 一、连接操作与提示

采用统一连接状态机，网络连接生命周期只允许一个控制流程持有。所有入口共享状态，不能仅靠某一个按钮禁用防重入。

| 情况 | 行为 |
| --- | --- |
| 点击加入 | 立即禁用按钮并显示“加入中…”；固定本次服务器地址与房间参数 |
| 加入中重复加入 | 静默合并，不再建立连接 |
| 收到有效入房快照 | 网络层立即接收和处理消息；按钮继续显示“加入中…”1 秒，期间连接仍正常才显示“已加入” |
| 已在同一服务器、同一房间 | 保持“已加入”禁用状态，不通过重复加入刷新快照 |
| 明确失败 | 结束本次尝试，在面板显示原因；从点击起至少 3 秒后重新启用加入按钮 |
| 一直无响应 | 建议整次手动入房 10 秒超时，终止本次尝试并重新启用按钮；不与后台重试同时运行 |
| 点击退出 | 立即取消待加入、连接中、成功等待和自动重连；清空房间状态，异步清理连接 |
| 快速退出再加入 | 只保留最新加入意图，旧连接清理完成且距上次连接尝试至少 2 秒后执行 |
| 已加入后网络断开 | 自动退避重连，沿用原加入参数；面板显示“正在重连”，重复加入不另外创建连接 |

这里将用户“加入完成后隔 1 秒再正式进入加入状态”解释为成功显示延后 1 秒，不暂停底层收包。退出可立即中断该等待。

合并以最新用户意图为准：退出取消之前的加入；退出后新的加入才允许重新连接。操作代次同时约束异步清理、延迟、连接完成和回调，禁止旧操作恢复连接或覆盖新状态。编辑地址/房间不暗中迁移当前连接；新参数与当前会话不同可发起一次明确切换，复用同一控制流程。

正常重复操作、节流等待与临时断网不弹窗。配置错误、房间满、身份被替换等在面板提供简短可操作提示；任务发布未确认仍给出反馈，不假报成功、不跨会话重发。保留服务端现有资源限制，补充有界的跨连接入房限流作为兜底；阈值和计数保留时间通过正常重连、多用户场景测试确定，避免同一公网 IP 的正常玩家相互影响。

## 二、设置入口与本地记忆

- 从 `src/SettingsPanel.cs` 移除嵌入的 `RoomSettingsPanel`，仅保留设置中的独立“联机”标签；原入口仍可跳转该标签。
- 继续使用现有 `UserData/settings.json` 的 Multiplayer 配置，不新建第二套配置。
- 联机地址、房间码、Callsign 编辑后通过合并保存落盘；加入、关闭设置与正常退出程序前确保最后编辑值已经保存，不能只依赖失去焦点事件。
- 启动恢复上次输入，连接失败或退出房间不清空这些值；启动自动加入仍遵守用户原开关。
- 保存中的旧视图不得覆盖新配置。保持原子替换写入和独立 UID 文件，失败时保留可见反馈。

## 三、名字与身份同步

统一语义：UID 表示身份；所有显示位置使用该身份最新已知的显示名，不固定解算发生时的旧名。

- 服务端任务的解算者改为 UID 引用；成员、任务发布者、本地历史以 UID 关联名字。
- 房间维护最新身份表；改名和重名后缀变化更新身份表并发送增量事件，无须逐条改写任务。
- 入房快照包含身份表。离线成员移除后，仍被服务端任务引用的身份继续保留；无成员、无任务引用时可回收，防止身份表随进出无限增长。
- 解算者累计集合也必须有明确容量约束：不能让不断更换 UID 的用户造成任务和快照无限增长；实施时确定上限、达到上限后的协议行为并加入边界测试。
- 客户端收到名字更新，刷新成员、任务发布者、已解算/正在解算、本次历史；重连快照同样更新本地缓存。缓存按服务器与房间作用域隔离，避免不同房间重名编号相互覆盖。
- 客户端退出房间后只知道最后收到的名字，不声称能同步别处的改名。本地历史保留所需的最新名字缓存，不随成员移除回退到旧名。
- 这属于协议变更：先定义新契约与版本策略，配套更新 Go/C#；不让旧版客户端误读新版消息。上线前明确旧版客户端的兼容或升级提示路径。

## 四、主动同步快照

- 新增 `sync` 请求，保持现有会话并返回当前房间快照，不重新 join、不清空任务、不改变 sessionId。
- 包含当前成员、任务和最新身份表；快照与 revision 保持一致，客户端原子应用，历史按任务 ID 去重。
- 客户端同一会话最多一个同步请求在途，重复请求合并，最小间隔建议 2 秒；服务端同样限频。普通改名依靠增量事件，不靠频繁快照。
- 在途同步由退出/切换取消。不要将 revision 数字跳跃直接当成丢包：现有房间 revision 也可能因只发给新成员的快照递增。

## 五、远端测试房 testzz4z

单独的机器人进程，通过正式 WebSocket 协议加入 `testzz4z`。两个固定 UID，显示名为“测试侦察兵 BOT”和“测试炮兵 BOT”。自动重连、开机启动，机器人在线使房间常驻。首版默认模拟解算，用来验证共享和解算者标记，明确记录它不是射表正确性验收。

| 真人触发 | 机器人行为 |
| --- | --- |
| 非机器人炮兵共享目标 (x,y)，且已有同地图炮位 | 虚拟侦察兵发布 (x+1,y+1) 的任务 |
| 真人炮兵先共享目标，之后补设同地图炮位 | 补触发一次虚拟侦察兵任务 |
| 非机器人侦察兵主动发布信标任务 (x,y) | 虚拟炮兵先设置炮位 (x+2,y+2)，再共享目标 (x,y) 并上报模拟 solved=true |

触发细则：

- target 共享与 publish 信标分开处理；目标共享关闭时无法触发新目标响应。
- 两个机器人的事件都不触发机器人逻辑，防止互相循环；不按显示名识别机器人。
- 比较成员前后状态；重名、炮位移动、solved 改变以及完整 member 重播不重复发布同一当前目标的回应。真人目标 A→B→A 属于新的目标变化，可以再响应。
- 信标按发布者会话与 taskId 去重；同坐标新 taskId 是新信标。机器人首次进入已有房间、重连快照仅建立基线，不自动重放历史任务；退出后清理过期去重数据。
- 多人信标按服务端顺序进入有界队列，逐条响应；每次模拟目标至少展示 1 秒。队列满时不继续无限积压，记录聚合计数，具体容量在实现中确定。
- 沿用触发点地图；偏移越界时跳过并记录原因，不夹紧、不变更用户要求的偏移。

部署目标：既有服务器 `/opt/wardogs` 下独立二进制/配置及 `wardogs-testbots.service`，低权限运行、资源限制、自动恢复，不额外开放公网端口。普通服务端继续使用 `wardogs.service` 和既有公网地址。

实际远端操作前读取本地 `.tools/ssh/服务器连接与操作规则.md`。操作前及期间检查相关持久化文件系统；上传、构建、安装等写盘前后检查，长任务持续检查。任一使用率超过 95% 立即停止后续服务器操作并告知；无法读取则暂停写盘；不自行删除数据绕过限制。优先本地构建并校验哈希，保存可回退版本，配套升级服务端后再启动机器人，检查既有服务正常。当前仅编制方案，尚未执行部署。

## 六、执行顺序与验收

1. 先明确协议版本、身份引用边界、sync 和机器人行为契约，更新协议文档。
2. 实现连接状态机、操作合并和配置保存，完成重复点击、取消与延迟测试。
3. 实现 Go 身份更新/sync/限流及 C# 对应处理，测试改名、重名、断线快照、本地历史一致性和容量边界。
4. 完成本次限定 UI 修改，实测按钮文字、禁用、10 秒超时、失败至少 3 秒恢复、成功延后 1 秒、退出即时取消、最后意图生效。
5. 实现机器人，先在本地真实服务上验证双方角色、模拟 solvedBy、多用户顺序、去重、防循环、地图越界及重连不重放。
6. 运行相关 Go 测试/vet、C# 真实互通和必要 WPF 回归；重启客户端核验地址、房间、Callsign 与开关恢复。同步刷新应保持会话和任务不变。
7. 产出联机版构建，按磁盘规则实施远端配套部署，真人连接 testzz4z 验证两条交互，记录版本、哈希、健康检查、服务恢复和磁盘用量。
8. 更新开发进度，逐项区分已实现、自动验证、人工验证和待验证；不把本机测试当成远端实机结论。
